Q: Is scene generation mixed into outline, or separate?

A: MIXED BUT FRAGMENTED
   ├─ Global scene chain: Planned AFTER outline (optional, reference only)
   ├─ Per-chapter scenes: Planned on-demand when opening chapter
   ├─ Manual scenes: Generated on user request (optional iteration)
   ├─ Chapter generation: INDEPENDENT, bypasses scenes entirely
   └─ State tracking: ONLY happens for manual scenes, not chapters

Current Positioning:
  1. Outline is the foundation
  2. Chapters are parsed from outline
  3. Scenes are OPTIONAL add-ons for state tracking
  4. Chapters are generated directly (not from scenes)
  5. Scenes provide state metadata (but not required for chapters)

If user wants chapters WITHOUT scenes:
  - /outline → finalize → /chapter/{N} (works perfectly)

If user wants to track state:
  - /scene/{N} generates scenes + extracts state changes
  - State updates applied to story_state.json

The architecture treats scenes and chapters as PARALLEL OPTIONS,
not as a dependency chain.

ANSWER TO YOUR QUESTION
───────────────────────────────────────────────────────────────────────────────

"Is scene generation mixed into outline, or is it separate?"

ANSWER: MIXED BUT FRAGMENTED

  ✓ Scenes are MIXED into the outline workflow:
    - Optional scene chain planning exists (post-outline)
    - Per-chapter scene planning is automatic (on-demand)
    - Scene state extraction is implemented (new in Phase 3)

  ✗ But scene generation is SEPARATE from chapter generation:
    - Chapters can be generated WITHOUT scenes (/chapter/{N})
    - Scene details = "" (EMPTY) in chapter prompt
    - Not the default generation path

  CURRENT POSITIONING:
    Outline → Chapters (PRIMARY - chapter-first)
              ↓
              Scenes (SECONDARY - optional add-on for state tracking)

  IF SCENES SHOULD BE PRIMARY:
    Outline → Scenes → Chapters (aggregate scenes)
              [Not the current architecture]
